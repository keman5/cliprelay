# 随贴 · ClipRelay

这是独立的 macOS 菜单栏应用、iOS 应用、键盘和分享扩展。原有 ClipNote 网页继续使用自己的账号和数据库。随贴以设备密钥建立信任，同网传输无需注册账号。

## 在本机试用

1. 打开 `/Applications/ClipRelay.app`。在 iPhone 或模拟器打开「随贴」，进入「设备」。首次发现设备时，允许访问本地网络。
2. 在 Mac 的「设备」页点「显示配对码」。在另一台设备输入 6 位码，核对指纹后确认信任。Mac 收到请求后也要确认信任。邀请有效期为两分钟，也可以展开「配对二维码」并扫码。
3. 找不到 Bonjour 设备时，新配对码会尝试直接连接邀请方的局域网地址。两台设备无法直连时，在「手动配对」中通过可信渠道交换请求码和确认码。配对后仍可在「局域网地址」中手动填写对端的私网 IPv4 和 TCP 端口。跨网传内容时，双方还要在设置中启用同一个云端中继。
4. 随贴在 Mac 上运行时，复制的文本、图片和文件默认自动加入历史，并发送到已配对设备。「设备 → 同步」可分别暂停自动保存或同步，也可手动发送。手机打开随贴后会从可连接的配对设备取回待发条目。历史里图片显示缩略图和大小，文件显示格式图标和大小。可在 Mac 设置中排除指定应用。
5. iOS 在「设置 → 通用 → 键盘 → 键盘 → 添加新键盘」添加随贴，长按地球键切换。基础打字可以直接使用。要从键盘访问共享历史或同步，需要在系统设置中允许完全访问。选中历史文本会插入光标处；富文本、图片或文件会按类型写入系统剪贴板，再由目标应用执行粘贴。也可在随贴中通过系统分享面板传给支持的应用。
6. iOS 键盘的自动保存和发送默认关闭，可在随贴设置的「键盘偏好」分别开启。键盘显示时会保存新复制的文字和链接。也可在键盘的剪贴板页面点「粘贴」图标手动保存到本机。系统可能询问是否允许粘贴。键盘和分享扩展将待发条目保存在本机，短时间内尝试发送小条目。大附件和未送达的内容在主应用活动时继续发送。

## iPhone 工作区

- 「历史」支持正文搜索、置顶、类型和来源组合筛选。点条目查看原件、上次复制时间、逐设备送达状态，或设置过期和复制后删除。纸飞机按钮可选择收件设备，在详情中可以取消尚未开始的发送。
- 「设备」支持配对、指纹比对、设备备注、测试文字、手动地址和成员目录。手机可在前台接力。系统挂起应用后，持续监听和后台接力取决于设备再次打开应用。
- 「设置」内可配置前台采集、自动发送、历史锁、脱敏、保留时长及备份。自动读取和发送默认关闭。在历史页点「开启自动保存」后，可在其他应用复制内容，回到随贴时读取最近一份剪贴板。iOS 询问时请允许粘贴，也可以直接点历史页的「粘贴」手动添加。iOS 无法向应用提供其他应用的剪贴板来源，敏感内容应使用手动粘贴。历史锁开启期间，键盘不展示共享历史和常用语。
- 系统「快捷指令」中可使用「打开剪贴板历史」。从其他应用取用内容还可切换至随贴键盘，或用系统分享菜单发送给随贴。

## 存储和备份

多设备可以逐台配对，也可让一台 Mac 在「成员目录」发布已配对设备。各端须显式选择信任该 Mac，才能取得它介绍的其他成员。目录最多 12 名直接成员。局域网内收到新名单时撤销立即生效，离线目录授权最多保留 120 秒。直接配对关系仍可独立使用云端。开启 Mac 的转发开关后，可以通过一台中间 Mac 接力。

- 单条原件和随附纯文本合计最多 10,000,000 字节。主应用接收完整附件，再允许粘贴。iOS 分享支持系统提供的文本、富文本、图像和文件表示。
- SQLite 历史每页 30 条，内存缓存最近 4 页摘要。其他扩展写入后会使旧页失效。普通历史最多保留最近 1,000 条，历史对象上限 160 MB；回收时保留收藏和等待发送的条目。待发密文和中继密文另有 100 MB、60 MB 上限。在设置页可查看实际占用、条数和分页查询耗时。
- 本机历史存放于应用数据目录；网络信封和导出备份各自加密。本机历史数据库采用系统文件保护和目录权限。导出的 `.clipnote` 使用备份口令和 AES-GCM；设备私钥、云端凭据不随备份导出。
- 在 iOS 设置页导出加密备份，通过系统分享传到 Mac，再在 Mac 设置页选中归档、输入口令并导入。同一归档可重复导入。导入 AuvCast 的 `.rayonclip` 时保留可恢复的文本、图片和收藏，跳过私密条目和只有旧机器路径的记录，并报告跳过数量。
- Mac 开启历史锁后，导出单条内容、导出全部历史、创建或分享加密备份均需通过系统身份验证。

## 测试中继

地址为 `https://cliprelay-test.macseek.cc`。Cloudflare Worker 接入独立私有 R2 桶 `cliprelay-test-ciphertext`；各收件设备解密验证、落盘成功后才删除自己的对象。未取件的对象配置了七天过期策略。

在 Mac 查看发送状态时，「已交给中继，送达未确认」表示中间 Mac 或云端已接手。目标设备保存内容并送回加密回执后，发送方显示「对方设备已接收」。使用旧版接收端或回执暂时无法返回时，会保留中继状态。

设备之间使用 CryptoKit 的认证模式 HPKE（Curve25519、SHA-256、ChaChaPoly）。每个收件人拥有自己的加密信封。同一测试中继的客户端共享投递凭据，列举、读取和删除还需要对应邮箱的读取凭据。本机部署凭据在 `~/.config/cliprelay-test/worker-secrets.json`，权限为 0600。配置客户端时只在其安全输入框中使用 `RELAY_TOKEN`。测试中继的共享写入凭据适合同一信任范围的小规模使用。

## 本地构建和复验

需要 Xcode、XcodeGen、Node 和可用的 Apple Development 签名。以下命令在仓库根目录执行。

```sh
scripts/build.sh
node cliprelay/scripts/verify.mjs
node cliprelay/scripts/verify-cloud.mjs
cliprelay/build.sh --mac-view-qa
cliprelay/build.sh --history-ui-qa
```

构建脚本更新版本，验证签名，安装到本机「应用程序」和专用模拟器 `ClipRelay-QA`。可用 `CLIPRELAY_SIM` 指定已有的模拟器。传输测试使用临时密钥、专用数据库和合成内容。自动测试会输出本次直连使用 Bonjour 还是模拟器回环。

复验包括双向文本、断开直连后的真实 R2 双向 10 MB 收发、凭据隔离、重复提交、错误口令、损坏数据、跨平台恢复、分页刷新和三个独立身份的一跳接力。Mac 视图用隐藏宿主检查，iOS 系统键盘需在模拟器内另外验收。

重新部署测试中继使用 `cliprelay/cloud/deploy.sh`，它复用本机凭据。完整设计和后续范围见 [项目设计](../docs/clipnote-device-clipboard-design.md)。

## App Store 本地打包

```sh
scripts/build.sh --app-store ios
scripts/build.sh --app-store macos
```

使用 Xcode 中配置的开发者团队和分发签名。本地归档和导出包（iOS 为 IPA，macOS 为 PKG）存放在 `${CLIPRELAY_BUILD_ROOT:-~/Library/Caches/ClipRelayBuild}/app-store`，按平台和构建号分目录。构建号自动生成，商店显示版本由 `project.yml` 的 `MARKETING_VERSION` 设置。
